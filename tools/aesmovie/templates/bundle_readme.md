# Full-motion video for your Neo Geo game

Generated by aesmovie {version}. Everything here is source, and it is
yours to read and change.

The movie plays as a blocking call. It takes the screen for as long as it
runs, then hands every register it touched back to you. That is what a
cutscene wants, and it is what keeps the surface small enough to fit on
one page.

## What you need

An ngdevkit project: a `Makefile`, a `rom.mk`, an autoconf `config.mk`.
If `make` builds a cartridge for you today, this drops into it.

## Dropping it in

**1. Copy this whole folder** into your project, next to `assets/`.

**2. Add one line to your `Makefile`,** between `include rom.mk` and
`include build.mk`. The order matters: the fragment adds its own source
directories to `SRCDIRS`, which `build.mk` reads.

```make
include rom.mk
include fmv/fmv.mk
include build.mk
```

**3. Name your own objects and pick up the flags,** before the include:

```make
FMV_GAME_OBJS = $(BUILDDIR)/main.o
CFLAGS += $(FMV_CFLAGS)
LDFLAGS += $(FMV_LDFLAGS)
PROM2SIZE = {prom2_size}
```

With `FMV_GAME_OBJS` set, the fragment declares one ELF per switchable
bank and wires each to its slice of the second program ROM. Leave it
empty to declare those yourself.

**4. Point the cartridge at the movie's ROM images.** The fragment
exports `$(FMV_MOVIE)` for exactly this, so the paths hold whatever you
named the folder:

```make
$(CROM1): $(FMV_MOVIE)/c1.bin
$(CROM2): $(FMV_MOVIE)/c2.bin
$(SROM1): $(FMV_MOVIE)/fix.s1
```

**5. Call it.** Four lines in your own source:

```c
#include "fmv.h"
#include "movie_data.h"

void play_intro(void)
{{
    fmv_options options = fmv_defaults();

    options.skip_pad = FMV_PAD_A | FMV_PAD_B;
    fmv_play(&fmv_movie_data, &options);
    game_redraw();
}}
```

`fmv_play` returns `FMV_FINISHED` when the movie reached its last frame
and `FMV_SKIPPED` when the viewer cut it short. Both give the machine
back the same way, so a caller that treats them alike is correct.

## The calls

| Call | What it does |
|---|---|
| `fmv_defaults()` | An options value with working defaults. Start here and change what you need |
| `fmv_play(movie, options)` | Plays to the end or until skipped, then restores everything. This is the whole API for a cutscene |
| `fmv_open(player, movie, options)` | Takes the screen and readies frame zero, for a caller driving its own loop |
| `fmv_start(player)` | Draws frame zero and starts the soundtrack |
| `fmv_tick(player)` | Advances one frame. Call once per vblank |
| `fmv_hold(player)` | Keeps the picture still and the palette upload running. This is what pause looks like |
| `fmv_seek(player, frame)` | Jumps to the nearest keyframe at or before a frame, audio with it |
| `fmv_close(player)` | Gives everything back. Every path out of a movie ends here |
| `fmv_ended(player)` | Non-zero once the last frame has been shown |
| `fmv_position(player)` | The frame the player is about to show |
| `fmv_last_updates(player)` | Slot updates the last tick wrote, for a caller measuring its own budget |

Nothing in that list reads a pad register unless you asked for it. Set
`options.skip` to your own predicate and the library never touches the
pad at all:

```c
static int viewer_wants_out(void *user)
{{
    return ((game_state *)user)->start_was_pressed;
}}

options.skip = viewer_wants_out;
options.skip_user = &state;
```

## What the movie owns while it plays

| Resource | This movie takes | Yours |
|---|---|---|
| Sprites | {first_sprite} to {last_sprite} | Everything else. Move them with `options.first_sprite` |
| Palette banks | {palette_base} upward | Below {palette_base}. Fixed at bake time, not a runtime option |
| C-ROM tiles | 0 to {last_tile} | {tile_count} upward. Pack your own tiles after the movie's |
| P-ROM banks | {stream_banks}, starting at `FMV_FIRST_BANK` | The other banks, and the whole fixed megabyte |
| Fix layer | Nothing | All of it. The library draws no text |
| LSPC mode, fix source, palette bank, bank latch | Saved on open, restored on close | Set them however you like before and after |

Two of those deserve a sentence.

**The palette base is a bake-time choice, not a runtime one.** A palette
number is baked into every tile word in the stream, so moving it means
re-baking with `--base-bank`. Everything else in the table moves at
runtime.

**Tile numbers are absolute.** The movie's dictionary occupies tiles 0 to
{last_tile}, so your own tiles start at {tile_count}. Bake with
`--tile-budget` to reserve room for yourself up front, before the
dictionary grows into the space you wanted.

## What it costs per frame

| Quantity | This movie |
|---|---|
| Frames | {frames} |
| Worst frame | {max_updates} slot updates |
| Worst frame, inner loop | about {tick_cycles} cycles |
| Blanking interval | about 18432 cycles |

The worst frame is a keyframe, which rewrites every slot on screen. The
cycle figure counts the per-tile inner loop only; a frame also pays a
setup per run, twenty of them on a keyframe. Read it as a floor.

For `fmv_play` none of this matters, because the movie owns the frame
while it runs. It matters when you drive `fmv_tick` yourself and want to
draw on top: on a keyframe there is close to nothing left, and
`fmv_last_updates` tells you what the frame just spent.

## Sound

This bundle was baked with audio: **{audio}**.

The video path needs no sound driver at all. Set `FMV_AUDIO` to `no` and
nothing references a Z80 symbol, so your own driver keeps the M1 ROM to
itself. That is the default worth taking for a game that already has
music.

To play the movie's soundtrack instead, the Z80 side has to host three
commands. `{library_dir}/sound.s` is the reference driver, supplied as
source to read or merge:

| Command | Meaning |
|---|---|
| `0x1n` | Shift nibble `n` into the ADPCM-B page counter. Four of these carry one page |
| `0x50` | Start playback from the page just shifted in |
| `0x60` | Stop |

`fmv_audio_cue` sends the four nibbles and then the start, once at the
beginning and once per seek. Merging this into a driver you already run
is not proven here, and the page arithmetic lives in
`{library_dir}/timeline.c` if you need to reproduce it.

## Version

The movie data and the library in this folder were emitted together and
are stamped {version}. Compiling one against a different version of the
other stops the build and names both versions. When that happens, re-bake
the movie or replace `{library_dir}/` with the copy that matches.

## Limits worth knowing before you start

- The C-ROM ceiling is 128 MiB with no bankswitching, and your tiles and
  the movie's come out of the same ceiling.
- The bank latch holds three bits, so `FMV_FIRST_BANK` plus
  {stream_banks} must not pass 8.
- Your own code must live in the fixed first megabyte. The library
  switches the bank latch to read the stream, so code running from a
  switchable bank disappears underneath itself.
- The picture is a fixed grid of sprites. There is no scaling and no
  rotation, and the movie cannot be drawn behind anything.
